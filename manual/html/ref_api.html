6.6. Programming interface¶

This section gives the reference data for each public module. The text comes from the documentation text in the source code.

You can import the primary names directly from the package annunciator. For example, from annunciator import get_logger and from annunciator.logger import get_logger give the same function.

6.6.1. Severities (annunciator.levels)¶

Severity levels.

This module defines the severity levels of the library. The levels agree with the numeric levels of the standard logging module. The library adds two levels: TRACE (5) and NOTICE (25).

Examples

>>> from annunciator import Severity
>>> Severity.coerce("warn")
<Severity.WARNING: 30>
>>> Severity.WARNING.letter
'W'

6.6.2. Structured loggers (annunciator.logger)¶

Structured loggers.

A StructuredLogger is a thin layer on a logger of the standard logging module. It adds message codes, structured fields and context data to each record.

Use get_logger() to get a structured logger.

Examples

>>> from annunciator import get_logger
>>> log = get_logger("demo.module")
>>> log.name
'demo.module'
>>> child = log.bind(sample="S-1")
>>> child.bound
{'sample': 'S-1'}

6.6.3. Context data (annunciator.context)¶

Context data for events.

Context data are key and value pairs that the library adds to each event. Typical examples are a run identifier, a sample name, or a user name.

The library keeps the context in a contextvars.ContextVar. Thus each thread and each asyncio task has its own context.

Examples

>>> from annunciator import bind, context, get_context, clear_context
>>> bind(run="R-17")
>>> with context(sample="CeO2-04"):
...     sorted(get_context().items())
[('run', 'R-17'), ('sample', 'CeO2-04')]
>>> get_context()
{'run': 'R-17'}
>>> clear_context()

6.6.4. Message catalogues (annunciator.catalogue)¶

Message catalogues.

A message catalogue is a set of message definitions. Each definition has a unique message code, a text template, a probable cause and a remedy.

A message code has three parts:

APP-E-0042
|   |  |
|   |  +-- message number (four digits)
|   +----- severity letter (T, D, I, N, W, E or C)
+--------- catalogue prefix (two to eight characters)

When you use message codes, each message has one definition. The log records, the exceptions and the user documentation then agree.

Examples

>>> from annunciator import MessageCatalogue, Severity
>>> cat = MessageCatalogue("DEMO", "Demonstration messages", replace=True)
>>> definition = cat.define(
...     1, Severity.ERROR, "The file '{path}' is not available.",
...     cause="The file does not exist.",
...     remedy="Make sure that the path is correct.",
... )
>>> definition.code
'DEMO-E-0001'
>>> definition.format(path="a.csv")
"The file 'a.csv' is not available."

6.6.5. Coded errors (annunciator.errors)¶

Coded exceptions.

A coded exception is an exception that has a message code, a probable cause and a remedy. All coded exceptions are subclasses of CodedError.

You can use the classes of this module directly. You can also make your own subclasses. Set the class attribute default_code to give a standard message code to a subclass.

Examples

>>> from annunciator import CodedError, MessageCatalogue
>>> cat = MessageCatalogue("DOC", replace=True)
>>> _ = cat.define(7, "E", "The detector '{name}' does not answer.",
...                remedy="Make sure that the detector has power.")
>>> class DetectorError(CodedError):
...     default_code = "DOC-E-0007"
>>> error = DetectorError(name="HPGe-2")
>>> str(error)
"[DOC-E-0007] The detector 'HPGe-2' does not answer."
>>> error.remedy
'Make sure that the detector has power.'

6.6.9. Handlers (annunciator.handlers)¶

Handlers.

A handler sends log records to a destination. This module adds four handlers to the handlers of the standard logging module:

  • ConsoleHandler writes to the current sys.stdout or sys.stderr.

  • EventStoreHandler keeps the last events in memory.

  • CallbackHandler gives each event to a function.

  • AsyncQueueHandler puts records in a queue for a different thread.

Examples

>>> import logging
>>> from annunciator.handlers import EventStoreHandler
>>> store = EventStoreHandler(capacity=10)
>>> logger = logging.getLogger("doctest.handlers")
>>> logger.addHandler(store)
>>> logger.propagate = False
>>> logger.warning("Low pressure")
>>> [event.message for event in store.events]
['Low pressure']
>>> store.counts()
{'WARNING': 1}

6.6.12. Handling tools (annunciator.handling)¶

Tools for error handling.

This module contains decorators and context managers that apply a standard policy to exceptions:

  • handle_errors() and guard record an exception. Then they raise it again, convert it, or stop it.

  • retry() does an operation again when it fails.

  • ErrorCollector collects many errors and raises them as one group.

  • log_calls() and timed() record calls and durations.

  • deprecated() issues a warning for an old function.

All decorators accept normal functions and coroutine functions.

Examples

>>> from annunciator import handle_errors
>>> @handle_errors(ZeroDivisionError, reraise=False, default=0.0)
... def ratio(a, b):
...     return a / b
>>> ratio(1, 0)
0.0

6.6.18. Integrity (annunciator.integrity)¶

Tamper-evident log files.

This module makes a JSON Lines log file with a chain. Each record contains a hash of the record before it. The records thus make a chain. If a person changes, removes or adds a record, the chain is broken and verify_chain() finds the position.

Each record has the object chain with three keys:

seq

The sequence number of the record. The first record has the number 1.

prev

The hash of the record before this record.

hash

The hash of prev and of the contents of this record.

Without a key, the hash function is SHA-256. With a key, the function is HMAC-SHA-256. A person who does not have the key cannot make a correct chain again after a change.

>>> handler.setFormatter(ChainFormatter())
>>> logger = logging.getLogger("doctest.integrity")
>>> logger.propagate = False
>>> logger.addHandler(handler)
>>> logger.warning("first")
>>> logger.warning("second")
>>> handler.close()

6.6.19. Multiprocess tools (annunciator.multiprocess)¶

Logs from many processes.

When many processes write to the same log file, the file can become damaged. The rotation of the file is not safe in this condition. This module sends the records of all worker processes through a queue to the primary process. Only the primary process writes the file.

The procedure has three steps:

  1. In the primary process, call configure(). Then call start_listener() to get the queue.

  2. Start each worker process with init_worker() as its initializer and the queue as its argument.

  3. At the end, call stop_listener().

Examples

import multiprocessing

from annunciator import configure, get_logger
from annunciator.multiprocess import init_worker, start_listener, stop_listener

def work(number):
    get_logger("worker").info("Item complete.", item=number)
    return number * number

if __name__ == "__main__":
    configure(file="logs/run.jsonl", file_format="json")
    queue = start_listener()
    with multiprocessing.Pool(4, init_worker, (queue,)) as pool:
        results = pool.map(work, range(100))
    stop_listener()

6.6.21. Lint (annunciator.lint)¶

The check reads Python source files without running them. It compares the message codes in the files with the registered catalogues. It finds three types of problem:

6.6.23. HTML report (annunciator.htmlreport)¶

HTML report of a run.

The function write_html_report() writes one HTML file that contains the events of a run. The file has no external parts. You can open it in a browser without a network connection and send it to other persons.

The page has the style of a printed industrial report: a title block, numbered sections and ruled tables in a fixed-width font, without colour. It shows the number of events for each severity and for each message code, the distinct failures and a table of the events. The reader can select events by severity, by message code and by text. A click on an event shows its fields, cause, remedy and traceback.

Examples

>>> import os, tempfile
>>> from annunciator import Event, Severity
>>> from annunciator.htmlreport import write_html_report
>>> events = [Event(severity=Severity.ERROR, message="No beam", code="APP-E-0001")]
>>> path = write_html_report(events, os.path.join(tempfile.mkdtemp(), "run.html"))
>>> path.read_text(encoding="utf-8").startswith("<!DOCTYPE html>")
True

6.6.25. Sphinx extension (annunciator.sphinxext)¶

Sphinx extension for message catalogues.

The extension adds the directive annunciator-catalogue and the role msg. The directive writes the reference text for all messages of a catalogue. Thus the documentation and the software always agree.

To use the extension, add "annunciator.sphinxext" to the list extensions in the file conf.py. Then write, for example:

.. annunciator-catalogue:: APP
   :module: myapp.messages
   :min-severity: WARNING

Refer to :msg:`APP-E-0001`.

The directive has these options:

module

A module to import before the directive reads the catalogue. Use this option for the module that defines your catalogue.

min-severity

Write only the messages of this severity or higher.

category

Write only the messages in this category.

heading

The character for the section underline. The default is ~.
