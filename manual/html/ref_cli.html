6.5. Command-line interface¶

6.5.1. Syntax¶

annunciator [--version] [-i MODULE] [-c FILE] COMMAND [ARGUMENTS]

If the terminal cannot find the command annunciator, use python -m annunciator with the same arguments.

6.5.2. General options¶

Put the general options before the command.

Table 6.18 General options of the command-line interface¶

Option

Function

--version

Shows the version of the library.

-h, --help

Shows the help text. You can also put this option after a command.

-i MODULE, --import MODULE

Imports a module that defines message catalogues. You can give this option more than one time.

-c FILE, --catalogue-file FILE

Reads a message catalogue from a JSON file or a TOML file. You can give this option more than one time.

6.5.3. Commands¶

6.5.3.1. catalogue¶

Shows the messages of the registered catalogues.

annunciator catalogue [--prefix PREFIX] [--min-severity SEVERITY]
                      [--search TEXT] [--format {text,json,rst}]
Table 6.19 Options of the command catalogue¶

Option

Function

--prefix PREFIX

Shows only the catalogue that has this prefix.

--min-severity SEVERITY

Shows only the messages of this severity or higher.

--search TEXT

Shows only the messages that contain this text.

--format FORMAT

text (default), json or rst.

6.5.3.2. explain¶

Shows the full definition of one message.

annunciator explain CODE

6.5.3.3. report¶

Shows a summary of a JSON Lines log file.

annunciator report PATH [--json] [--html FILE] [--title TEXT] [SELECTION]
Table 6.20 Options of the command report¶

Option

Function

--json

Writes the summary as a JSON object.

--html FILE

Also writes an HTML report of the selected events to the file.

--title TEXT

The title of the HTML report.

6.5.3.4. view¶

Shows the events of a JSON Lines log file in the plain text format.

annunciator view PATH [--no-help] [--csv FILE] [SELECTION]
Table 6.21 Options of the command view¶

Option

Function

--no-help

Does not show the cause and the remedy.

--csv FILE

Writes the selected events to a CSV file and shows no events.

6.5.3.5. check-config¶

Examines a configuration file and shows the value of each option.

annunciator check-config PATH

6.5.3.6. verify¶

Examines the integrity data of a JSON Lines log file.

annunciator verify PATH [--key-env NAME] [--expected-start HASH]
Table 6.22 Options of the command verify¶

Option

Function

--key-env NAME

The environment variable that contains the key. The default is ANNUNCIATOR_CHAIN_KEY.

--expected-start HASH

The last hash of the older file. Use this option for a file after a rotation.

6.5.3.7. diff¶

Compares the events of two JSON Lines log files.

annunciator diff FIRST SECOND [--json]

FIRST is the reference run. SECOND is the run to examine. The option --json writes the comparison as a JSON object.

6.5.3.8. lint¶

Examines the message codes in Python source files. Use the general option --import to load your catalogue.

annunciator lint PATH [PATH ...] [--prefix PREFIX] [--no-unused] [--strict]
Table 6.23 Options of the command lint¶

Option

Function

--prefix PREFIX

Examines only the catalogue with this prefix. You can give this option more than one time.

--no-unused

Does not show the codes that the source code does not use.

--strict

Gives the exit status 1 for unused codes also.

6.5.3.9. demo¶

Shows one example event of each severity and one event with a code.

annunciator demo

6.5.4. Selection options¶

The commands report and view accept the selection options. An event must agree with all given options.

Table 6.24 Selection options¶

Option

Function

--min-severity SEVERITY

Selects the events of this severity or higher.

--code PATTERN

Selects the events with a code that agrees with the pattern, for example "APP-E-*".

--logger PATTERN

Selects the events with a logger name that agrees with the pattern.

--text TEXT

Selects the events that contain this text in the message.

--fingerprint TEXT

Selects the events of the failure that has this fingerprint.

In a pattern, * agrees with all characters and ? agrees with one character. Put a pattern in quotation marks.

6.5.5. Exit status¶

Table 6.25 Exit status of the command-line interface¶

Status

Meaning

0

The command completed. For report: the log has no errors. For verify, diff and lint: the command found no problem.

1

For report: the worst severity in the selected events is ERROR. For verify: the integrity check failed. For diff: the second run has new problems. For lint: the source code has incorrect codes.

2

For report: the worst severity in the selected events is CRITICAL.

64

The command line is not correct.

66

The interface cannot import a module or cannot read a file.

Other

The exit status of the coded error that stopped the command. Refer to Table 6.9.

Note

You can use the exit status of report in a script to stop a sequence of steps when a run had errors.
